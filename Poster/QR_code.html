4. How trust works

Technical ideas are explained in plain English first, with more detail available if needed.

1. Record
Create a Decision Receipt

RAMIFY stores the important details of the decision.

2. Fingerprint
Create a digital fingerprint

SHA-256 creates a value that changes if the receipt changes.

3. Signature
Add a digital signature

Ed25519 helps confirm that the receipt came from the expected source.

4. Check
Verify before action

If the record does not match, RAMIFY stops the workflow.

ReceiptCanonical record

Decision, evidence references and metadata.

IntegritySHA-256

Detects changes in receipt content.

AuthenticityEd25519

Checks the digital signature.

ControlAction Gate

Requires a valid receipt before action.

Receipt is valid

The fingerprint matches and the signature is valid. RAMIFY treats the record as unchanged and lets the workflow continue.

Receipt was changed

The fingerprint or signature does not match. RAMIFY blocks the final action or sends the case for review.

7. More technical detail

These stay collapsed so non-technical visitors are not overloaded.

The frontend presents the Identify → Resolve → Status → Verify → Assess journey. It also supports onboarding, persona colour coding and decision-state visibility.

FastAPI handles requests, validation and workflow transitions. The decision layer tracks options, state, readiness and whether the user can continue.

The Decision Receipt records the outcome together with evidence references and metadata so the decision can be reviewed later.

SHA-256 helps detect content changes. Ed25519 helps verify the digital signature. Together they support receipt integrity and authenticity checks.

The demo can run locally on 127.0.0.1. Optional local AI support can be used without making the receipt verification process depend on the AI model.
