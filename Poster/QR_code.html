06 · Human review

A review should add history, not erase it

If a person needs to intervene, RAMIFY can preserve the original receipt and create a successor receipt for the reviewed outcome.

Original Receipt

The first signed decision record remains available as part of the history.

→

Human Review

A reviewer records the reason for the intervention and the updated outcome.

→

Successor Receipt

A new signed receipt is created and linked back to the earlier one.

This avoids silently overwriting the earlier decision. A reviewer can see both the original state and the later human-reviewed continuation.

08 · Technical notes

For reviewers who want the deeper version

The page stays readable for non-ICT visitors, while the technical details are still available here.

A receipt separates the auditable decision record from the temporary user interface state. It can carry the outcome, evidence references, metadata and verification material in one place.

The Action Gate sits after verification. In the intended flow, it requires the necessary signed receipt checks to pass before the action proceeds; an invalid or tampered record can be blocked or sent for review.

The demo deliberately changes receipt content and then shows verification failing. That demonstrates the integrity mechanism as behaviour, not just as text on the screen.

The demonstration is designed to run locally on 127.0.0.1. Optional Ollama support can provide a local model path, while receipt verification remains a separate trust mechanism.
